## 1. Что это

Сеть, где владельцы обычных ПК отдают свои GPU под большие модели. Control Plane
на VPS принимает запросы по OpenAI-совместимому API, ставит их в очередь,
выдаёт узлам по аренде и собирает ответ потоком. Главная идея — **шардирование**:
модель, которая не влезает в одну видеокарту, делится по слоям между
участниками. Без этого проект не нужен: запустить 8B на своей карте человек
может и без платформы.

## 4. Что сломано и что не сделано

Честный список, по убыванию важности.

1. **GPT-OSS-20B считается штатным llama.cpp, не своим пайплайном.** Файл
   `ggml-org/gpt-oss-20b-GGUF`, `gpt-oss-20b-MXFP4.gguf`, 12 ГБ, лежит в диске
   WSL. Сборка CUDA внутри WSL, build 10671. Контекст 4096, `--n-cpu-moe 22`:
   при 16 слоях экспертов на CPU карта не приняла буфер 424 МиБ. После загрузки
   занято 3564 МиБ из 8151. Промпт «The capital of France is». Холодное
   продолжение: 5 токенов промпта за 3.25 с (1.54 tok/s), 32 новых за 5.11 с
   (**6.07 tok/s**). Текст начинается с ` Paris."`, дальше список столиц;
   температура сервера по умолчанию 0.8, это не жадная сверка. Чат со шаблоном
   Harmony: первые 32 токена ушли в канал рассуждения (11.00 tok/s), поле ответа
   пустое. Повтор с тем же промптом, 67 токенов уже в кэше: 35 токенов за 1.79 с
   (**19.02 tok/s**), ответ `Paris`. Windows-сборка b12167 тот же файл через
   `\\wsl$` не прочитала: «сетевое имя более недоступно». Python-пайплайн
   остаётся прототипом на 0.52 tok/s; safetensors этого прогона удалены, без
   новой загрузки его не повторить. Qwen3-0.6B: 32 токена совпадают с кэшем
   целой модели.
2. **Пайплайн не интегрирован с платформой**: диапазоны слоёв, туннель для
   активаций, аттестация по частям — не подключены.
3. **Холодный старт удалённой стадии долгий** (десятки минут при домашней
   отдаче 1.4 МБ/с). Решается тем, что узел качает свои слои сам (это и есть
   смысл нового рантайма).
4. **Petals не годится** — проверено, см. архив §3.28: только bloom/falcon/llama/
   mixtral, последний релиз 2023-11-20, не ставится на Python 3.12.
5. **Панель**: нет страницы «мой вклад» для участника, бинарник не подписан
   (SmartScreen ругается).
6. **Платформа**: нет второй площадки Control Plane, нет Anthropic-протокола
   `/v1/messages` (поэтому Claude Code без переходника не подключить).
7. **RAG заморожен** (есть документы, поиск и страница, но нет корпуса и
   потребителя), эмбеддинги — этап 9 в паузе.

## 6. Целевые модели

Критерии отбора — не размер, а: лицензия, позволяющая хостить и раздавать веса;
архитектура, которую наш рантайм умеет резать; разреженность (MoE) для ёмкости;
спрос у клиентов (агенты, код).

### Флагман для шардирования: MoE, не dense

| Модель | Актив / всего | Лицензия | Зачем |
|---|---|---|---|
| **GPT-OSS-120B** | 5.1B / 117B | Apache 2.0 | родной MXFP4 ≈ 63 ГБ на всю сеть; узел считает как 5B — **цель для демо** |
| Qwen3.5-122B-A10B | 10B / 122B | Apache 2.0 | 256K контекст, 201 язык, мультимодал |
| Qwen3-Coder-Next 80B-A3B | 3B / 80B | Apache 2.0 | SWE-bench 70.6 при 3B активных: кодинг почти бесплатен по вычислениям |
| Step-3.5-Flash | 11B / 196B | Apache 2.0 | MTP-3 из коробки (1.5–3× декод), 350 tok/s |
| GLM-4.5-Air | 12B / 106B | MIT | сильная математика, дешёвая лицензия |

### Dense-класс (проще всего для нашего рантайма)

| Модель | Размер | Лицензия | Роль |
|---|---|---|---|
| Qwen3.5-9B | 9B | Apache 2.0 | замена `qwen3:8b` в быстром классе |
| Llama 3.3 70B | 70B | Llama Community (EU ok) | понятная демонстрация «не влезает в одну карту» |
| QwQ-32B / R1-Distill-32B | 32B | Apache 2.0 / MIT | рассуждения, 2 узла |
| Muse-Glimmer-30B | 30B | Apache 2.0 | агентный кодинг на потребительском железе |

### Чего избегать

- **Llama 4 / Llama 3.2 Vision** — лицензия исключает ЕС для мультимодальных.
- **Mistral Medium 3.5, MiniMax** — Modified MIT с потолками выручки/MAU: модель
  «подорожает» ровно тогда, когда сеть вырастет.
- **DeepSeek-V4-Flash 284B** — MIT и 1M контекст, но Q4 ≈ 156 ГБ: рано.
- **Гибридные архитектуры** (Qwen3.8-27B, Ling, Kimi-Linear, Nemotron) — нужен
  перенос рекуррентного состояния вместо KV-кэша; вторая версия рантайма.

### Несколько моделей одновременно

Платформа уже маршрутизирует задания по `served_model` каждого узла, поэтому
разные узлы могут держать разные модели. Не хватает **пулов**:

| Класс | Как обслуживается | Пример |
|---|---|---|
| `fast` | реплики на одиночных узлах | Qwen3.5-9B |
| `capacity` | шард-группа (топология) | GPT-OSS-120B |
| `code` | отдельный пул | Qwen3-Coder-Next 80B-A3B |
| `embed` | мелкий пул (уже есть) | nomic-embed-text |

Для пулов нужны: учёт ресурсов при вступлении узла (VRAM/RAM уже в heartbeat),
прогрев по спросу и вытеснение по популярности. Ограничение: каждая модель —
это диск и трафик участника, поэтому каталог должен оставаться маленьким
(4–6 моделей).

## 7. Как проверить

```bash
# Go: сборка и тесты (на этой машине обязательно так — иначе не хватит памяти)
$env:GOMAXPROCS='2'; go build -p 1 ./... ; go test ./internal/...

# панель и API на проде
node tools/browser_check.mjs
node tools/scheduler_e2e.mjs

# прототип пайплайна (WSL)
bash tools/wsl_mesh_env.sh                     # один раз: venv + torch
MODEL=Qwen/Qwen3-0.6B SPLIT=14 TOKENS=24 bash tools/wsl_run_pipeline.sh

# состояние платформы (нужен пароль root, он не в репозитории)
python tools/ssh_run.py "systemctl is-active api-gateway"
```

Полезные скрипты: `tools/vps-deploy-gateway.sh` (выкладка Control Plane),
`tools/vps-last-jobs.sh`, `tools/vps-mesh-state.sh`, `tools/vps-traffic.sh`,
`tools/vps-tunnel-cleanup.sh`.

## 8. Грабли, которые уже стоили времени

| Грабля | Что делать |
|---|---|
| Сборка падает с OOM | `GOMAXPROCS=2`, `go build -p 1`, при нужде остановить узел и `ollama stop qwen3:8b` (лимит commit ~31 ГБ) |
| KV-кэш 16K на 8 ГБ не влезает рядом с рабочим столом | `OLLAMA_KV_CACHE_TYPE=q4_0` на картах ≤ 9 ГБ (установщик выбирает сам) |
| Два параллельных запроса поднимают два llama-server и оба падают | `OLLAMA_NUM_PARALLEL=1` |
| Порт 18081 занимает Ollama (её собственный llama-server) | проверять порт перед стартом шард-группы |
| TCP-опрос `ggml-rpc-server` рвёт активную RPC-сессию | стадию проверять только по живости процесса, порт опрашивать лишь у координатора |
| `client_max_body_size 16m` в nginx обрезает поток туннеля | отдельный `location` с `client_max_body_size 0` |
| Выкладка gateway: забыл `chmod 0755` | 203/EXEC и сервис лежит; после `mv` всегда `chmod`, затем `systemctl reset-failed` |
| Файлы конфигов узла с BOM | писать JSON через `UTF8Encoding($false)`, иначе `parse config: invalid character` |
| PowerShell ломает кавычки в командах для SSH | писать `.sh` файл и запускать через `tools/ssh_put.py` + `bash` |

## 10. Договорённости

1. **Не придумывать числа.** Всё, что попадает в документы как «измерено», должно
   быть видно в выводе инструмента.
2. **Ошибку сообщать сразу**, включая свои: в архиве есть разборы, где я сначала
   винил память, а виноват был TCP-опрос.
3. **`nasushno` и Proxmox — только чтение.**
4. **Секреты не в репозитории.** Пароль VPS передаётся владельцем отдельно.
5. **Проверка после выкладки:** `api-gateway` + `health`, плюс `nasushno`,
   `nginx`, `postgresql` — `active`.
6. **Без «долгих загрузок» в продукте:** холодный старт должен укладываться в
   минуты, иначе участники не поймут, что происходит.
