# Узел на Linux

Окно программы есть только на Windows. На Ubuntu Server тот же агент ставится и управляется командами. Служба называется `compute-node`. Модель на видеокарту сама не встаёт: она загружается, когда подключённый узел забирает сообщение из чата.

Перед установкой `nvidia-smi` уже должен показывать видеокарту. Драйвер NVIDIA программа не ставит.

Файл программы: `https://api.nshno.tech/node/compute-node-linux`. Это Linux-сборка той же версии, что и Windows-программа. Файл `compute-node.exe` на сервер с Ubuntu не подойдёт.

## Установка

```bash
curl -fL -o compute-node-linux https://api.nshno.tech/node/compute-node-linux
chmod +x compute-node-linux
sudo ./compute-node-linux setup --code <код сети>
```

`setup` делает то же, что окно на Windows:

- ставит Ollama 0.34.2, если её ещё нет, и запускает её службу;
- ставит llama.cpp b12167 (`llama-server` и `ggml-rpc-server`) в `~/.compute-network/llama`, сборка CUDA 13.4 или 12.8 по выводу `nvidia-smi`;
- регистрирует узел и скачивает модель целиком;
- копирует программу в `/usr/local/bin/compute-node` и включает службу systemd.

Повторный `setup` не создаёт второй узел, если конфигурация `/etc/compute-network/agent.json` уже есть.

Код сети нужен, только если владелец его включил. В команду его подставляет человек, у которого этот код есть.

## Данные для подключения

В конце `setup` программа сама пишет памятку и печатает путь к ней:

```text
/etc/compute-network/connection.txt
```

В файле лежат базовый URL, имя модели и ключ API, плюс примеры для клиентов. На экран ключ целиком не выводится. Открыть памятку:

```bash
sudo cat /etc/compute-network/connection.txt
```

Эти три поля вставляются в программу чата на том компьютере, где пишут сообщения. Харнес на самом сервере заполняется только если он там уже установлен. На обычном Ubuntu Server его нет, поэтому адрес и ключ переносят в харнес на рабочем компьютере.

Повторный `setup` новый ключ не выдаёт: узел уже зарегистрирован, памятка остаётся прежней.

## Команды

| Команда | Что делает |
|---|---|
| `sudo compute-node start` | снова берёт задания. Видеокарта пока пустая |
| `sudo compute-node stop` | отключает узел от сети и снимает модель с видеокарты |
| `sudo compute-node pause` | не берёт новые задания и снимает модель с карты, служба при этом жива |
| `sudo compute-node resume` | снова разрешает брать задания |
| `compute-node status` | показывает конфигурацию, не печатая секрет целиком |
| `sudo compute-node update` | скачивает новую Linux-сборку и перезапускает службу |
| `compute-node version` | печатает версию |

`stop` соответствует кнопке «Отключиться от сети». Останавливаются llama-server Ollama и процессы группы слоёв из каталога нашей сборки. Чужой `llama-server` не трогается.

## Что узел делает после запуска

Пока компьютер один, модель считается целиком через Ollama. Когда в сети два или больше компьютеров с llama.cpp и файлом модели, платформа сама выдаёт непрерывные диапазоны слоёв. Стадия на чат не отвечает: сообщения забирает ведущий компьютер. Подробнее — в [how-it-works.md](how-it-works.md).
