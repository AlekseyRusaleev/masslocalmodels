# Доступ к панели: аккаунты, пароли, сессии

Панель управляется **аккаунтом платформы и паролем**, а не административным
ключом. Ключи остались там, где они уместны: в программах участников и в узлах —
это машины, им пароль не подходит.

## Как завести первый вход

На сервере Control Plane, от пользователя `root`:

```bash
# 1. создать администратора и выпустить ему API-ключ (ключ понадобится только
#    для скриптов и программ, в панели он больше не нужен)
/opt/compute-control/bin/api-gateway bootstrap-admin admin@example.com

# 2. задать пароль входа в панель — без аргумента он читается из stdin, чтобы
#    не остаться в истории команд и в списке процессов
/opt/compute-control/bin/api-gateway set-password admin@example.com
```

Дальше вход на https://control.nshno.tech: почта и пароль. В «Настройках» этот
пароль можно сменить самостоятельно — сервер при смене отзывает все прежние
входы, включая текущий, и сразу выдаёт новую сессию, чтобы панель не выкинула
человека на форму входа.

Пароль: не меньше 10 символов, хранится только как bcrypt-хеш (cost 12). Если
пароль потерян, администратор задаёт новый той же командой `set-password`.

## Роли

| Роль | Что видит | Что может |
|---|---|---|
| `admin` | все разделы | узлы, приглашения, топологии, задания, аккаунты, метрики |
| `user` | чат, модели, настройки | пользоваться моделью и своей статистикой |

Роль задаётся при создании аккаунта и попадает в набор прав сессии. Разделы
«Узлы», «Топология» и «Задания» участнику не показываются: они про чужое
железо. Прямая ссылка вроде `#nodes` участника тоже не пустит — панель
переводит его в чат, а API отвечает `403`.

## Управление аккаунтами

Через панель: «Настройки» → «Доступ к панели» (виден только администратору).
Там создаётся аккаунт, задаётся роль, и отдельной кнопкой — пароль.

Через API:

```bash
# создать аккаунт сразу с паролем
curl -sS -X POST https://api.nshno.tech/admin/v1/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"ivan@example.com","name":"Иван","role":"user","password":"длинный-пароль"}'

# задать пароль существующему аккаунту
curl -sS -X POST https://api.nshno.tech/admin/v1/users/<user-uuid>/password \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"password":"длинный-пароль"}'
```

## Сессии

| Параметр | Значение |
|---|---|
| Срок жизни | 7 суток с момента входа |
| Хранение | браузер: `localStorage`; сервер: `auth_sessions`, только HMAC-хеш секрета |
| Токен | `ses_<key_id>.<secret>`, показывается один раз — в момент входа |
| Отзыв | «Настройки» → «Активные входы» → «Закрыть», в том числе для этого устройства |
| Смена пароля | отзывает все сессии аккаунта и выдаёт новую |

Проверка при запросе: подпись секрета (HMAC-SHA256 с pepper), срок, отзыв,
статус аккаунта и scope. Каждое использование обновляет `last_used_at` — по
нему в панели видно, каким устройством давно не пользовались.

Ограничение перебора паролей: не больше 10 неудачных попыток за 10 минут на
пару «адрес + почта». Счётчик живёт в памяти процесса (перезапуск его
обнуляет — это осознанный компромисс, отдельного хранилища попыток нет).

## Метрики

`GET /metrics` — формат Prometheus, только администратору:

```bash
curl -sS https://api.nshno.tech/metrics -H "Authorization: Bearer $ADMIN_TOKEN"
```

| Метрика | Смысл |
|---|---|
| `compute_workers{state}` | узлы по состоянию |
| `compute_workers_serving` | узлы, заявившие модель для чата |
| `compute_worker_context_tokens_{min,max}` | окно контекста, которое держат узлы |
| `compute_jobs{state}` | задания по состоянию |
| `compute_job_tokens_total{direction}` | токены входа и выхода, обработанные узлами |
| `compute_job_generation_seconds_total` | суммарное время генерации |
| `compute_sessions_active` | действующие входы в панель |
| `compute_accounts{role}` | аккаунты по роли |
| `compute_api_keys_active` | действующие ключи программ |
| `compute_conversations` | диалоги панели, которые хранит сервер |
| `compute_conversation_messages` | сообщения в этих диалогах |
| `compute_control_uptime_seconds` | время работы процесса |

Метрики не содержат имён узлов, адресов и ключей: это агрегаты.

## История диалогов

Разговор из панели хранится на сервере и принадлежит аккаунту: с другого
устройства он открывается под тем же аккаунтом, а чужой диалог не читается и не
удаляется (ответ `404`, как на несуществующий).

| Что | Где |
|---|---|
| Список диалогов | слева от разговора: название, число сообщений, когда обновлялся |
| Новый разговор | кнопка «Новый» в списке; запись создаётся при первом запросе, старые остаются в списке |
| Удаление | значок корзины в строке диалога |
| Хранение | `conversations` и `conversation_messages`, текст и счётчики токенов |

Что важно знать: сохраняется и вопрос, и ответ — включая оборванный остановкой.
Если сохранить не удалось, панель пишет об этом отдельной строкой: ответ уже
показан и не пропадает, но в историю не попадёт.
