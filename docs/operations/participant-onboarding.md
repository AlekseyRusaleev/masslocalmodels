# Подключение машины участника

Один файл: `compute-node.exe`. Он же установщик с окном и прогрессом, он же
значок в трее, он же агент, который обслуживает задания. Отдельного второго
файла рядом не нужно.

Требования к железу и опросник — в [`participant-requirements.md`](participant-requirements.md).

## 0. Как это выглядит на машине

| Что | Где видно |
|---|---|
| Агент узла | тот же `compute-node.exe`, запущенный с командой `run` — без окна консоли |
| Управление | значок в трее: открыть окно, пауза/возобновление, панель в браузере, выход |
| Журнал | окно установщика и `%TEMP%\worker-setup.log`; журнал агента — `logs\worker-agent.log` рядом с конфигом |
| Автозапуск | задача планировщика запускает `compute-node.exe --run`: окно не показывается, виден только трей |

Постоянно открытой командной строки нет: программа собрана как оконная
(`windowsgui`), а режим агента запускается с флагом скрытого окна.

## 1. Установка одной командой (основной путь)

Всё, что нужно участнику: скачать архив, распаковать и выполнить одну команду с
кодом приглашения из панели (Узлы → Подключить компьютер):

```powershell
.\install-worker-agent.ps1 -Invite <код из панели> -Binary .\compute-node.exe
```

Скрипт делает всё сам:

| Шаг | Что происходит |
|---|---|
| 1 | копирует `compute-node.exe` в `C:\ComputeNetwork\bin` |
| 2 | регистрирует узел по приглашению (модель берётся из приглашения, имя — из компьютера) |
| 3 | проверяет железо и Ollama, при необходимости скачивает модель с прогрессом |
| 4 | измеряет скорость и отправляет калибровку |
| 5 | вставляет маршрут `compute-network` в настройки харнеса DeepSeek Harness |
| 6 | создаёт задачу автозапуска и запускает её: в трее, без окна консоли |

Проверено на чистой конфигурации: команда доходит до `[100%] готово`, задача
создаётся, узел появляется в панели со статусом «Доступен».

Что может пойти не так и что делать:

| Сообщение | Причина и действие |
|---|---|
| `name_taken` | узел с таким именем уже зарегистрирован: удалите старый узел в панели или передайте `-Name другое-имя` |
| `enrollment token already used` | приглашение одноразовое: выпустите новое в панели |
| `модель не задана` | в приглашении нет модели и её не указали через `-Model` |
| `Ollama не отвечает` | установите Ollama и запустите её один раз, затем повторите команду |

## 2. Способы запуска

| Способ | Команда | Когда нужен |
|---|---|---|
| Обычный | запустить `compute-node.exe` | участник сидит за компьютером |
| Без лишних кликов | `compute-node.exe --invite "<код>" --auto` | удалённая машина, скрипт раздачи |
| Только трей | `compute-node.exe --run --config <файл> --model qwen3:8b` | автозапуск |
| Команды агента | `compute-node.exe join|run|status|benchmark|...` | терминал, отладка |

Аргументы графического режима: `--invite` (код из панели), `--name` (имя узла),
`--model`, `--task-name` (если на машине несколько узлов).

## 3. Что показывает окно

| Элемент | Смысл |
|---|---|
| Поле «Код приглашения» | вставить строку из панели (Ctrl+V работает) |
| Имя узла | можно переопределить, пустое имя — имя компьютера |
| «Подключиться» | запускает весь путь, прогресс-бар показывает шаг и проценты |
| «Включить автозапуск» | задача планировщика при входе; запускает это приложение в трее, без прав администратора |
| «Открыть папку узла» | где лежат конфиг и `harness-settings.yaml` |
| Журнал | каждое действие с временем; дублируется в `%TEMP%\worker-setup.log` |
| Трей | закрытие окна прячет его в трей, узел продолжает работать; меню: открыть окно, пауза/возобновление, панель в браузере, выход |

Модель участник не выбирает: установщик спрашивает у платформы, какая модель
обслуживается сетью (та, у которой больше узлов), и скачивает именно её. Если её
нет в Ollama — загрузка идёт автоматически, с процентом по байтам. Настройки
харнеса обновляются сами, в том числе когда сеть переключается на другую модель.

После успешного подключения установщик сам запускает агент и оставляет
приложение в трее — дополнительных действий не нужно.

## 4. Что происходит по шагам

| Шаг | Детали |
|---|---|
| 1 | проверка железа: CPU, RAM, GPU, VRAM; отказ, если GPU нет или VRAM меньше 8 ГБ |
| 2 | проверка Ollama и модели; при необходимости загрузка с прогрессом по байтам |
| 3 | регистрация по одноразовому токену; секрет устройства шифруется DPAPI |
| 4 | калибровка: короткая генерация, скорость уходит на сервер |
| 5 | запись `harness-settings.yaml` рядом с конфигурацией узла |
| 6 | по кнопке — задача автозапуска и запуск агента |

Конфигурация выбирается так: сначала `%ProgramData%\ComputeNetwork`, но только
если туда реально можно писать; иначе `%LOCALAPPDATA%\ComputeNetwork`. Установщик
не притворяется, что сохранил файл, если прав не хватило — путь печатается в журнале.

## 5. Настройки для харнеса

Установщик сам вставляет маршрут в `%APPDATA%\DeepSeekHarness\data\settings.yaml`
и ключ в `.credentials.yaml`, если харнес на машине найден. Перед правкой
делается резервная копия `<файл>.bak-<дата>`. Если структура файла незнакомая
(например, `providers` записан потоково `{...}`), установщик файл **не трогает** и
сообщает, что вставить вручную — так чужая конфигурация не портится.

Фрагмент, который он добавляет (и который печатает `harness-settings.yaml`):

```yaml
llm-pi-ai:
  providers:
    compute-network:
      displayName: Compute Network
      api: openai-completions
      baseURL: https://api.nshno.tech/v1
      apiKeyEnv: COMPUTE_NETWORK_API_KEY
      defaultContextWindow: 16384
      defaultMaxTokens: 4096
      models:
        - id: "qwen3:8b"
          name: "qwen3:8b"
          contextWindow: 16384
          maxTokens: 4096
          inputModalities: [text]
```

Ключ участника — в `refs` того же каталога:

```yaml
refs:
  COMPUTE_NETWORK_API_KEY: dai_...
```

Оба файла перечитываются на лету, перезапуск не нужен, но **новый чат**
обязателен: состав доступных моделей сессия запоминает при старте.

## 6. Что нужно на машине заранее

| Компонент | Зачем |
|---|---|
| Windows 10/11 x64 | платформа установщика и агента |
| NVIDIA GPU от 8 ГБ VRAM | считает модель |
| Ollama | локальный рантайм (`ollama serve`) |

Модель скачивать вручную не нужно: галочка «Скачать модель, если её нет»
(в режиме `--auto` она включена) скачает её сама.

## 7. Шифрование: что именно защищено

| Что | Как защищено | От чего |
|---|---|---|
| Канал до платформы | TLS 1.2+ | перехват в сети |
| Секрет устройства | DPAPI (учётная запись и машина) | копия конфига на другой машине не работает |
| Ключи на сервере | HMAC-SHA256 с серверной «перцовкой» | утечка БД не даёт действующих ключей |
| Текст запросов в БД | **не шифруется** | — |

Сквозного шифрования запросов нет и в этой схеме быть не может: платформа
обязана видеть текст, чтобы направить его нужному узлу и вернуть ответ.

## 8. Проверка

| Где | Что смотреть |
|---|---|
| Окно установщика | «узел подключён», прогресс 100 % |
| `%TEMP%\worker-setup.log` | все шаги с временем; при сбое — строка `ОШИБКА` |
| Панель `https://control.nshno.tech` | «Узлы»: новая строка, модель, температура, скорость калибровки |
| Машина | `compute-node status`, журнал `worker-agent.log` с `heartbeat ok` |

## 9. Управление узлом

| Действие | Как |
|---|---|
| Пауза / возобновление | панель → «Пауза» / «Возобновить», либо `compute-node pause` / `resume` |
| Удалить из каталога | панель → корзина → «Удалить» |
| Убрать автозапуск | `.\install-worker-agent.ps1 -Uninstall` или `schtasks /Delete /TN "ComputeNetwork Worker Agent"` |
| Сменить модель | `compute-node run --model другая:модель` (модель запомнится) |

## 10. Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| окно не открылось, процесс живёт | запустили из папки с ограниченными правами | запустить обычным двойным щелчком |
| `приглашение не распознано` | строка обрезана при пересылке | вставить целиком или передать файл |
| `enrollment token already used` | токен одноразовый и уже израсходован | выпустить новое приглашение в панели |
| `Access is denied` при сохранении | нет прав на ProgramData | установщик сам уходит в `%LOCALAPPDATA%`; проверить журнал |
| «Ollama недоступна» | рантайм не запущен | `ollama serve` и повторить |
| окно закрылось, а узла нет | установщик свернулся в трей | двойной щелчок по значку в трее |
| `unprotect device token` | конфиг скопирован с другой машины | пройти подключение заново |
