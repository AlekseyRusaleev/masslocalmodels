# Требования к участнику и опросник для рекрутинга

> Таблица ниже писалась до первых участников и часть пунктов в ней шире того, что программа проверяет. Сейчас участник запускает Windows-программу. Она сама ставит Ollama и llama.cpp. Видеокарты, кроме NVIDIA, программа не видит. Единственная измеренная карта — 8 ГБ. Файл модели скачивается целиком, для `gpt-oss:20b` это около 14 ГБ на диске, а не отдельный раздел на 60 ГБ. Как это устроено: [`../how-it-works.md`](../how-it-works.md).

Документ отвечает на два вопроса: что спросить у человека и что платформа соберёт сама.

Связанные документы: [`ADR 0006`](../adr/0006-mvp-single-worker.md), план §7 (Worker Agent), §13.2 (режимы доверия).

---

## 1. Минимальные требования

| Категория | Требование | Зачем |
|---|---|---|
| ОС | Windows 11 (x64) или Linux Ubuntu 22.04/24.04 | Worker Agent ставится как служба |
| GPU | NVIDIA, **≥8 GB VRAM**, RTX 3060 и новее | помещается модель нужного класса |
| Драйвер | рабочий `nvidia-smi`, драйвер свежее 550, CUDA ≥12.4 | иначе runtime не запустится |
| RAM | ≥16 GB **и ≥8 GB свободной закоммиченной памяти** в момент работы агента | кроме VRAM нужен контекст и загрузчик; модель 8B требует ≈2.3–3 GB commit, плюс ОС и браузеры |
| Диск | ≥60 GB свободно на отдельном разделе | кэш весов; не на системном |
| Сеть | upload ≥20 Mbit/s, желательно ≥100 | Worker забирает задачу и отдаёт результат |
| NAT | публичный IPv4 или возможность исходящего соединения | входящие порты не нужны, но CGNAT усложняет релей |
| Время работы | ≥8 часов в сутки в доступном окне | иначе узел бесполезен для очереди |

Отказ без обсуждения: GPU без поддержки CUDA (Kepler и старше), ≤4 GB VRAM, ноутбук с перегревом под длительной нагрузкой, диск с <20 GB свободного места.

## 2. Вопросы кандидату

Отправлять текстом, ответы заносить в его карточку узла.

1. Какая ОС и версия? Windows 11 или Linux, точный билд.
2. CPU (модель), сколько ядер и потоков, сколько RAM всего и сколько реально свободно в обычной работе?
3. Модель GPU и объём VRAM. Второй GPU есть? Встроенная графика используется для вывода?
4. Версия драйвера NVIDIA и поддерживаемая CUDA (`nvidia-smi` — колонка CUDA Version).
5. Сколько свободного места на каком диске? Готов ли отдать отдельный раздел под кэш?
6. Провайдер и скорость: upload/download по замерам, есть ли публичный IP или CGNAT?
7. В какие часы компьютер обычно включён? Играете ли на нём — в какое время?
8. Готовы ли принимать чужие вычисления в простое, или только свои задачи?
9. Понятно ли, что GPU-узел видит входные данные приватных задач того пула, к которому подключён?
10. Сколько готовы держать агент установленным — неделя, месяц, бессрочно?

## 3. Что соберёт агент автоматически

При `POST /worker/v1/enroll` агент отправляет discovery-пакет (см. `worker_capabilities`):

```json
{
  "token": "<одноразовый токен подключения>",
  "name": "owner-pc",
  "hostname": "DESKTOP-WORKER01",
  "os": "windows 11 26100",
  "agent_version": "0.1.0",
  "hardware": {
    "cpu_model": "AMD Ryzen 5 5600X 6-Core",
    "cpu_cores": 12,
    "ram_bytes": 17074585600,
    "gpus": [{
      "name": "NVIDIA GeForce RTX 5060",
      "vram_bytes": 8547991552,
      "driver_version": "617.14",
      "cuda_version": "13.4",
      "compute_capability": "12.0"
    }],
    "disks": [{"mount": "D:\\", "free_bytes": 205924515840, "total_bytes": 268435456000}],
    "cuda_version": "13.4",
    "driver_version": "617.14",
    "network": {"upload_mbps": 940, "nat": false}
  }
}
```

Собирается только техника: модели, объёмы, версии, свободное место, состояние сети. **Не собираются** имена файлов, содержимое каталогов, список процессов пользователя, история браузера, серийные номера в открытом виде.

## 4. Что платформа обещает владельцу железа

1. **Пауза в один клик**: `POST /admin/v1/workers/{id}/state` → `paused`; агент получает `desired_state` в ответе на heartbeat и прекращает брать новые задания. Активные — завершаются или отменяются по политике владельца.
2. **Локальные лимиты**: максимум GPU/CPU, резерв RAM, бюджет диска под кэш — это ограничения владельца, а не тариф платформы.
3. **Режим «не трогать во время игр»**: агент сам ставит паузу по списку процессов и порогу GPU utilization.
4. **Никакого произвольного кода**: контейнеры только из allow-list, без privileged, без Docker socket, без доступа к домашнему каталогу и системному диску.
5. **Никаких ключей расшифровки**: агент не получает доступ к пользовательской БД и секретам платформы.
6. **Прозрачность**: панель участника показывает, что сейчас загружено, сколько места занято, какие задания выполнялись, сколько CU начислено.
7. **Отвязка**: `drain` → удаление сертификата/ключа на сервере → локальные данные по выбору владельца.

## 5. Кого звать и кого не звать

**Звать:** владельцев десктопов с одной-двумя NVIDIA GPU, кто и так держит компьютер включённым; небольшие студии с простаивающими машинами; тех, кому нужен доступ к моделям, которых не хватает их собственному железу.

**Не звать в MVP:** владельцев ферм (ломают fair-share и доверие), машины без CUDA, VPS без GPU (инференс не пойдёт), тех, кто ждёт денег — в MVP нет выплат и токена, только внутренний учёт вклада.

## 6. Куда записывать результат

После enrollment узел появляется в `GET /admin/v1/workers` с GPU, VRAM, свободным диском и последним heartbeat. Ответы из §2, которые не выводятся из железа (часы работы, готовность к чужим задачам, срок), хранить как заметку владельца узла — в поле `trust_class` конвертируется уже осознанно: `private` по умолчанию, `public` только после отдельного согласия.
