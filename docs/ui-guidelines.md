# UI/UX правила (методика unslop)

**Источник:** [github.com/heydamir/unslop](https://github.com/heydamir/unslop) — Damir Sokolovsky ([@heydamir](https://x.com/heydamir)), лицензия **CC BY 4.0**.
Правила ниже — адаптация методики под нашу платформу. Атрибуция обязательна при цитировании: сохраняйте имя автора и ссылку на репозиторий.

**Статус:** обязательно к исполнению для всех панелей и клиентов (`web/`, worker UI, любые HTML-прототипы).

---

## 0. Метод в одном абзаце

Vibecoded-интерфейсы проваливаются предсказуемо: всё светится, у каждой подписи эмодзи, отступы случайные, копирайт кричит. Unslop чинит ремесло, а не продукт: состав экранов и их порядок сохраняются, меняется то, что каждый размер, цвет, слово и изображение становится осознанным. Работа идёт как redline-ревью дизайнера: один слой за раз, по всему экрану.

## 1. Направление проекта (direction)

Пишется до правок, выводится из продукта, а не из трендов:

- **Продукт.** Приватная распределённая сеть: пользователь получает LLM через один API, участник отдаёт свой GPU и видит свою телеметрию; администратор управляет узлами, моделями и очередью.
- **Характер.** `спокойный, точный, приборный` (ледяной нейтральный, без эмоций; слова «clean, modern, minimal, premium» запрещены — они описывают любой шаблон).
- **Мир.** Приборная панель и ночная смена: светодиоды статуса, сетка измерений, моноширинные цифры, тишина вокруг одного яркого показателя.
- **Моменты.** Один на экран: живой график загрузки GPU/VRAM на панели участника; таблица узлов с честным статусом на админ-панели; карточка модели с реальными размерами артефактов в реестре.
- **Подпись.** Живая точка статуса узла (accent, 6 px) и табличные цифры в моно — используется последовательно и только там, где речь о состоянии.

Если у продукта появится настоящий логотип и цвет — они остаются и направление строится вокруг них. Фиолетово-синий градиент, блёстки и свечение — это slop, даже если они в логотипе.

## 2. Запрещено (это и есть «slop»)

- Градиенты между оттенками на поверхностях, gradient text, цветные свечения и цветные тени, радиальные заливки и «блобы» за контентом, неоновые рамки.
- Эмодзи в интерфейсе: в подписях, заголовках, кнопках, статусах. Всё, что было эмодзи-иконкой, становится линейной иконкой.
- Бейджи `New ✨`, `PRO`, `Beta 🚀`, `AI-powered` на всём подряд.
- ПОДПИСИ КАПСОМ С ШИРОКИМ ТРЕКИНГОМ.
- `animate-pulse`/`animate-ping` на неживых элементах, shimmer на заголовках, «дыхание» свечения, парящие элементы, параллакс, `transition-all`, `hover:scale` на карточках.
- Стеклянные панели, зерно, шум, bento-сетки как декор — замена одного тренда другим не считается улучшением.
- Заголовки-приветствия (`Welcome back, Damir! 👋`), восклицательные знаки, точки в конце коротких подписей, слова-хайп (`supercharge`, `seamless`, `unlock`, `magic`).
- Непроверяемые утверждения (`Loved by 10,000+ teams`, `10x faster`), выдуманные данные и плейсхолдеры вида `[X]` или `123,456`.

## 3. Обязательно

### Сетка и отступы
- Всё на сетке 4 px; одинаковые вещи — одинакового размера; внутри группы отступ меньше, чем между группами.
- Иконки в одной колонке, подписи на одной линии, числа выровнены по правому краю.
- Плотность: компактные панели 16, карточки 20–24, края страницы 24–32; навигация — самая плотная часть (строки 32–36, зазор 2–4).

### Цвет
- Одна нейтральная шкала с лёгким оттенком мира; фон, поверхности, границы и текст — из неё.
- Три роли текста: основной, вторичный, приглушённый. Не десять оттенков.
- Один accent, используется редко: главное действие, выделение, один важный показатель. Контраст accent с текстом ≥ 4.5:1.
- Семантические цвета (зелёный/красный) только по смыслу и приглушённо.
- Границы — тихие волосяные линии, 6–10 % прозрачности от цвета текста. Глубина на тёмной теме — ступени поверхностей, не тени.
- Градиент допустим только как сдвиг внутри одного нейтрального оттенка (активная строка `#2b2b2b → #1f1f1f`), никогда между разными оттенками.

### Типографика
- Одно семейство для интерфейса + максимум одно партнёрское (моно для цифр и метаданных).
- Несколько размеров из шкалы, веса 400/500, редко 600. Иерархия — размером и цветом, не весом.
- Sentence case везде. Никакого курсива для акцента. Никакого отрицательного трекинга на мелком тексте.
- Цифры — `tabular-nums`, один формат на экран.

### Иконки
- Один набор (lucide, если своего нет), один размер (16 или 18 px), один штрих (1.5).
- Цвет — от роли текста, никогда собственный. Ширина бокса иконки одинаковая во всех строках.

### Копирайт
- Заголовок говорит, что продукт делает и для кого, так, чтобы не подошёл другому продукту.
- Короткие метки (`Search`, не `Search anything...`). Изменение всегда с базой сравнения: `+12 % к прошлому месяцу`.
- Данные в макетах — правдоподобные (реальное число узлов, реальные модели), а не `42`.

### Графики
- Один главный график на экран, остальные данные — списком с тонкими полосами или короткой таблицей.
- Приглушённая сетка, моно-подписи, один accent на графике, остальные серии — нейтральные ступени.
- Тип графика по данным: тренд — линия, сравнение — столбцы, доля — одна составная полоса, цель — прогресс.
- Никаких «радужных» столбцов внутри одной серии и светящихся баров.

### Карточки показателей
- Подпись, крупное число, изменение с базой сравнения. Никаких спарклайнов и мини-баров «для заполнения».
- Сетка с ритмом: 3–4 компактных показателя в ряд над одним широким графиком, а не шесть одинаковых карточек.

### Раскладка
- Приложение занимает вьюпорт: сайдбар 240–280, контент текучий с ограничением ~1440–1600.
- Активное состояние — небольшая ступень поверхности с подсветкой-волоском, не градиент со свечением.
- Ховер и фокус есть всегда, в палитре, с видимым фокус-кольцом для клавиатуры.

### Движение
- Анимируется только то, что объясняет: ховер как быстрое изменение цвета, нажатие как микро-масштаб, появление меню как сдвиг на несколько пикселей, изменение числа — твин.
- Одна кривая и несколько длительностей на весь экран; переходы именованные (`transition-colors`), не `transition-all`.
- Не анимировать width/height/top/left/margin и большие blur. Не более одного появления при загрузке.

## 4. Чек-лист перед сдачей экрана

- [ ] Направление записано, все проходы ему следуют
- [ ] Все отступы кратны 4, одинаковые вещи одинакового размера
- [ ] Иконки, подписи и числа выровнены по колонкам
- [ ] Одна нейтральная шкала, три роли текста, один accent с достаточным контрастом
- [ ] Нет градиентов между оттенками, свечений, цветных теней, блобов
- [ ] Ни одного эмодзи в интерфейсе
- [ ] Один набор иконок, один размер, один штрих
- [ ] Веса 400–600, нет капса с трекингом, нет курсива
- [ ] Нет восклицательных знаков, приветствий, непроверяемых утверждений
- [ ] Числа в одном формате, табличные цифры
- [ ] Вложенные радиусы складываются: внутренний = внешний − отступ, минимум 4
- [ ] Первый экран скомпонован целиком, без мёртвой полосы
- [ ] Нет зацикленного и пружинного движения
- [ ] **Проверка на шаблон:** если подставить название другого продукта, экран всё ещё подойдёт? Если да — усилить направление в копирайте, визуале и подписи

## 5. Как это применяется к нашим экранам

| Экран | Момент (единственный яркий) | Что убираем в первую очередь |
|---|---|---|
| User Workspace | лента ответа с реальным потоком и цифрами токенов | эмодзи-статусы, градиентные кнопки, «AI-powered» бейджи |
| Contributor Dashboard | живой график GPU/VRAM + точка статуса | пульсации, свечения карточек, мини-графики в каждом стате |
| Admin Console | таблица узлов со честными статусами | шесть одинаковых карточек, радужные графики |
| Model Registry | карточка ревизии с реальными размерами и хешами | «New ✨», плейсхолдерные числа, капс-подписи |
| Worker Settings | переключатели с внятными последствиями | эмодзи-иконки, `transition-all`, всплывающие подсказки-простыни |

Макеты в `assets/` — концептуальные референсы композиции, а не эталон стиля: при расхождении с этим документом приоритет у этого документа.

## 6. Чего не делать

- Не переименовывать продукт и не ломать реальный логотип.
- Не менять суть продукта, набор функций и порядок разделов без запроса.
- Не заменять убранный декор новым декором.
- Не придумывать функции, утверждения и данные.
- Не скатываться к одному и тому же виду для всех экранов.
