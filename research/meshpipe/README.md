# prototip пайплайна слоёв (`research/meshpipe`)

**В продукт не входит.** Считает llama.cpp, как описано в [`docs/how-it-works.md`](../../docs/how-it-works.md).
Этот каталог — проверка идеи «каждый узел читает свои блоки, по сети идут только активации».
На GPT-OSS-20B она дала 0,52 tok/s и дальше не развивалась.

Здесь лежит прототип рантайма, который задумывался вместо llama.cpp RPC:
каждый узел держит свои блоки модели и свой KV-кэш, между узлами идут только активации.

## Цель

**GPT-OSS-120B** (Apache 2.0, MoE 5.1B активных из 117B, родной MXFP4 ≈ 63 ГБ).
Причина выбора — в `docs/STATUS.md`, раздел «Целевые модели»: разреженность даёт
и ёмкость, и скорость, а лицензия не мешает расти сети.

## Что уже проверено

| Проверка | Результат |
|---|---|
| torch на этом железе (WSL2, RTX 5060) | 2.15.0+cu132, CUDA 13.2, `capability (12, 0)`, bf16 matmul |
| плотная модель, разрез 14/14 | Qwen3-0.6B, 3.5–5.7 tok/s |
| MoE модель, разрез 1/2 | `yujiepan/qwen3-moe-tiny-random` — работает, то есть блоки с экспертами режутся так же |
| передача активаций | float32 по TCP, свой заголовок, без pickle |
| сверка с целой моделью | 8 токенов совпадают и с полным пересчётом, и с кэшем; 32 токена совпадают с кэшем целой модели |

Инкрементальный шаг починен (2026-11-06). В transformers 5 forward среза не
читает `cache_position`, а длину кэша берёт у слоя 0. После разреза блоки
сохраняли исходные номера, вторая стадия писала ключи мимо слоя 0, и каждый
новый токен получал позицию 0. Теперь `layer_idx` внутри среза начинается с
нуля, а в модель передаются `position_ids`.

На 32 токенах полный пересчёт целой модели (`fidelity.py`) и её же генерация
с кэшем расходятся на токене 28. Разрез совпадает с кэшем, не с полным
пересчётом: это разница порядка bf16 у самой модели, её же показывает
`cache_control.py`. Проверка: `pipeline_demo.py check --max-new-tokens 32`.

## Прогон GPT-OSS-20B

GPT-OSS-20B прогнан 2026-11-06 на двух процессах одной машины (WSL2, RTX 5060).
Разрез 12/12. Промпт `The capital of France is`, 8 новых токенов за 15.3 с,
0.52 tok/s. Ответ начинается с ` Paris."`. Первое слово верное. Целой модели
для побайтовой сверки в память не помещается. Прогон, где внимание второй
половины оставалось на процессоре, дал 18.6 с (0.43 tok/s) и хвост
`Sure! Here's a simple`. Хвост разошёлся, когда это внимание тоже переехало
на видеокарту: порядок bf16. Прогон, где эксперты считались на процессоре,
дал те же «Paris."» за 304.2 с.

Каждая половина: 1.68 ГиБ своих весов. Блоки экспертов, 4.73 ГиБ на половину,
читаются с диска только на время прохода слоя. Файл целиком 12.82 ГиБ, слои
лежат вперемешку в трёх шардах, чужие тензоры в память не копируются.
Пик CUDA при загрузке первой половины 0.60 ГиБ (внимание). Эмбеддинг 1105 МиБ
остаётся в оперативке: одно выделение CUDA на 1.08 ГиБ здесь не проходит.
Выбранные эксперты читаются с диска пачками по четыре и распаковываются на
видеокарте. Последний набор из не более чем четырёх экспертов остаётся на
видеокарте, пока процесс занял меньше 1.2 ГиБ. Более жирный кэш на обеих
половинах вытесняет распаковку на процессор: тот же ответ за 80.2 с
(0.10 tok/s). Внимание обеих половин на видеокарте, эмбеддинг и lm_head
в оперативке.

Плотный safetensors по-прежнему: Qwen3-0.6B, 0.70 ГиБ из 1.40, пик CUDA одного
процесса 0.99 ГиБ.

## Штатный llama.cpp

Тот же промпт посчитан 2026-11-06 сборкой llama.cpp CUDA (build 10671) из
`gpt-oss-20b-MXFP4.gguf`. Контекст 4096, `--n-cpu-moe 22`. Холодный декод:
32 токена за 5.11 с, **6.07 tok/s**, текст начинается с ` Paris."`. Чат со
шаблоном Harmony на повторном запросе, когда промпт уже в кэше: 35 токенов
за 1.79 с, **19.02 tok/s**, ответ `Paris`. При `--n-cpu-moe 16` видеокарта не
приняла буфер 424 МиБ. Windows-сборка b12167 этот файл через диск WSL не
прочитала. Для скорости GPT-OSS используется этот путь, не распаковка в
`pipeline_demo.py`.

## Как запускать

Окружение (один раз, в WSL):

```bash
bash tools/wsl_mesh_env.sh      # venv ~/mesh-py + torch
bash tools/wsl_mesh_deps.sh     # transformers, numpy, huggingface_hub
```

Прогон на одной машине (два процесса):

```bash
MODEL=Qwen/Qwen3-0.6B SPLIT=14 TOKENS=24 bash tools/wsl_run_pipeline.sh
```

GPT-OSS-20B тем же скриптом не гоняется. Два процесса, venv `~/mesh-py`:

```bash
HF_HUB_DISABLE_XET=1 CUDA_VISIBLE_DEVICES=0 CUBLAS_WORKSPACE_CONFIG=:16:8 \
  python research/meshpipe/pipeline_demo.py second \
  --model openai/gpt-oss-20b --split 12 --port 31331 --device cuda

HF_HUB_DISABLE_XET=1 CUDA_VISIBLE_DEVICES=0 CUBLAS_WORKSPACE_CONFIG=:16:8 \
  python research/meshpipe/pipeline_demo.py first \
  --model openai/gpt-oss-20b --split 12 --peer 127.0.0.1:31331 --device cuda \
  --max-new-tokens 8 --prompt "The capital of France is"
```

Файлы:

| Файл | Что делает |
|---|---|
| `pipeline_demo.py` | два процесса: координатор и стадия, активации по TCP |
| `baseline.py` | обычная генерация для сравнения текста |
| `fidelity.py` | эталонные токены (жадно, шаг за шагом) |
| `cache_control.py` | контроль: кэш против без кэша на одной модели |
| `inspect_config.py` | конфиг модели (слои, head_dim, sliding window) |
